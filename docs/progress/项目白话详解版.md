## 零、一句话版本

你们做的东西是：**用户丢一张小红书式的种草图上来，系统告诉 ta「这张图有没有被修过、修在哪、图里的变美效果到底是产品造成的还是修图造成的」，并且每一句话都能给出依据。**

现在的状态是：**骨架、流程、文案分析、OCR 都是真的；但最核心的"看图"能力还是假的。** 而且讽刺的是——**能用的真模型其实已经存在了，只是没接上去。**

## 一、名词对照表（白话 → 技术名）

### 1. 产品/赛题层

| 名词 | 人话 |
|---|---|
| **种草内容 / 种草文** | 小红书、抖音上那种"姐妹们这个粉底绝了"的推荐内容 |
| **底妆** | 粉底液、遮瑕、气垫这类打底的化妆品（你们锁定的第一个场景） |
| **Before / After** | 化妆前 vs 化妆后的对比图，种草文里最常见也最容易造假的形式 |
| **妆效归因（Beauty Effect Attribution）** | 核心卖点。判断"变好看了"到底**是粉底的功劳，还是磨皮滤镜的功劳**。赛题原话是"这个变美效果到底是不是产品造成的" |
| **四级结论** | `Verified 已验证` / `Partially Suspicious 部分可疑` / `Insufficient Evidence 证据不足` / `High-risk Misleading 高风险误导`。注意：**不是简单判真假**，证据不足就老实说不足 |
| **创作者补证（Creator Evidence Review）** | 创作者被质疑后，可以上传原相机原图/原始视频自证清白，系统重新核验。这是"双向保护"的关键——你们不打假，是保护消费者**和**创作者 |
| **可信凭证 / Trust Card** | 最终展示给用户看的那张结果卡片 |
| **Main Agent** | 总指挥。它自己不检测任何东西，只负责：调度 5 个工具 → 收集证据 → 按规则分级 → 生成人话解释 |
| **Tool（工具）** | 5 个各司其职的检测小模块，见架构图 |
| **结构化证据层** | 所有工具输出的统一格式 JSON。"可解释"的物理载体——每个结论都能往回追到是哪条证据 |

### 2. 图像取证层（这块名词最密）

| 名词 | 人话 |
|---|---|
| **EXIF / XMP** | 照片自带的"拍摄档案"：相机型号、时间、光圈快门、有没有用 Photoshop。**但社交平台上传时通常会把它剥掉**，所以只能"尽力而为" |
| **C2PA / Content Credentials** | 新一代的"照片出生证明"。拍的时候就在文件里写一份带加密签名的记录，之后每次编辑都记一笔，谁改过一查便知。Adobe、微软、尼康在推。**理想很美，但现在绝大多数图没有**，所以不能依赖它 |
| **SHA256** | 文件指纹。改一个字节指纹就变，用来证明文件没被动过 |
| **OCR** | 把图片里的文字识别出来（你们用的 PP-OCRv5，百度飞桨的） |
| **retouching（修图/修饰）** | 特指美颜类修饰：磨皮、美白、瘦脸、大眼 |
| **skin smoothing / whitening / face reshape / texture loss** | 磨皮 / 美白 / 瘦脸 / 皮肤纹理丢失（磨皮的副作用，毛孔细节没了） |
| **exposure / white balance / color temperature** | 曝光（亮度）/ 白平衡 / 色温（冷暖）。这三个是**全局调色**，不是美颜，但同样会让 before/after 失真 |
| **splicing（拼接）** | 把两张图拼成一张 |
| **inpainting（局部重绘）** | 用 AI 把图里一块抹掉并重新画（比如把痘印抹掉） |
| **local replacement（局部替换）** | 把图里某个局部换成别的东西 |
| **manipulation map（篡改定位图）** | 一张热力图，标出"哪些像素被动过" |
| **integrity score（完整性评分）** | 0–1 的分数，越高越"完整没被动过" |
| **reliability map（可靠性图）** | 告诉你在哪些区域上，模型的判断是可信的 |
| **Grad-CAM** | 一种画热力图的方法，显示"模型做判断时主要看了哪里"。**注意：它不等于篡改定位**，只是"模型关注的地方" |
| **TruFor** | 学术界一个很有名的图像篡改检测模型，能同时输出完整性评分 + 定位图 + 可靠性图 |
| **困难负样本（hard negative）** | 最容易误判的情况：天然皮肤好的人、柔光拍摄、HDR、JPEG 压缩、手机自带降噪——这些**不是修图但看起来像修图**。误报率就是在这批样本上测的 |
| **shortcut risk（走捷径风险）** | 模型没学会真本事，而是靠"修过的图分辨率刚好都是 1024"这种无关特征蒙对了。**这是最阴险的失败模式**，测试分数会虚高 |

### 3. 模型/训练层

| 名词 | 人话 |
|---|---|
| **CNN（卷积神经网络）** | 最经典的看图模型架构 |
| **EfficientNet-B0** | 一个轻量好用的 CNN，你们 V2 模型用的就是这个 |
| **YOLO / YOLO11n-seg** | 目标检测模型。`-seg` 版本不只画框，还能勾出精确的轮廓区域。你们用它定位"脸上哪些区域被修了" |
| **multitask（多任务）** | 一个模型同时预测好几个标签（比如同时判断"磨皮/美白/瘦脸"） |
| **checkpoint / 权重文件** | 训练完存下来的模型本体，就是那些 `.pt` 文件 |
| **inference（推理）** | 用训练好的模型去跑一张新图（相对的是 training 训练） |
| **ground truth（真值）** | 人工确认过的标准答案。没有它就算不出准确率 |
| **Macro-F1 / F1 / Precision / Recall** | 常见的准确率指标，F1 是综合分，0–1 越高越好 |
| **TPR / FPR** | 真阳性率（该抓的抓到了多少）/ 假阳性率（没问题的被误判了多少）。**FPR 对你们特别重要**——把没修图的说成修图了，会伤害创作者 |
| **阈值（threshold）** | 分数超过多少就判为"修过"。调高减少误报、调低减少漏报 |
| **confidence / calibration（置信度 / 校准）** | 模型说"我有 90% 把握"，但真实正确率只有 70%——这就叫没校准 |
| **端到端（end-to-end）** | 从用户上传一路跑到出报告，全链路打通 |
| **联调** | 把两个人分别写的模块接在一起跑通。通常是项目最容易卡的地方 |
| **接口冻结（API freeze）** | 把模块之间传递的数据格式定死不再改。**太晚冻结，全员都会卡住** |
| **mock（模拟实现 / 假数据）** | 用一个写死的假结果顶替真实功能，先把流程跑通。**做原型很正常，但拿去演示就是假的** |
| **LLM / DeepSeek** | 大语言模型。在你们系统里**只负责把结论翻译成人话，不参与判断真假** |

### 4. 数据集

| 名词 | 人话 |
|---|---|
| **FFHQ** | NVIDIA 的 7 万张高清人脸数据集。**注意：里面是 AI 生成的假脸，不是真人照片** |
| **FFHQR** | 把 FFHQ 那些脸请人做专业修图后的配对版本，所以天然构成"原图 vs 修图"配对 |
| **RetouchingFFHQ** | 更大的细粒度数据集（65 万+ 张），标注了磨皮/提亮/瘦脸/大眼四类操作**和强度等级** |
| **PPR10K** | 人像修图数据集，偏**全局调色**（曝光、白平衡、曲线），不是美颜 |
| **域差距（domain gap）** | 训练数据和真实场景长得不一样。FFHQ 是 AI 假脸，真实种草是手机拍的真人 + App 滤镜 + 平台压缩——**在假脸上跑到 99% 也不代表真图能用** |
| **泛化（generalization）** | 模型在没见过的新数据上还灵不灵 |
| **按身份划分（identity split）** | 划分训练/测试集时，保证**同一个人不会同时出现在两边**。否则模型背住了这张脸，分数虚高 |

## 三、现在做到了什么（详细）

### 3.1 主工程（`TrueGlow 映真/`）— 成员 1 + 成员 5

**架构（这些都是真的、能跑的）**：
- `backend/app/agent/`：planner 任务拆解 → router 调度 → orchestrator 编排 → fuser 证据融合 → **grader 风险分级** → reporter 报告生成
- `backend/app/tools/`：5 个 Tool 的接口骨架全部就位

**分级规则（grader.py）写得很扎实**——这是项目的灵魂，也是最值钱的部分：
- C2PA 缺失 ≠ 伪造，只标记 Unknown
- 检测结论要结合可靠性，低可靠性证据不单独定罪
- 判"高风险误导"需要多种证据相互印证（例：磨皮 High + 文案说"原相机零滤镜" → 才升级）

## 四、卡点（按严重程度排序）

### 🔴 卡点 1：能用的真模型没接上（最严重）

`Mirror-of-Truth` 里有三个训练好的模型和现成的 HTTP 接口，`TrueGlow 映真` 里**一行引用都没有**（全量 grep 无 torch / 无 Mirror-of-Truth / 无 visual_evidence 消费代码）。

模型在 A 仓库，产品在 B 仓库，中间是断的。结果就是演示时"图像鉴伪"这一栏是写死的假数。

**这本来是成员 2/3 自己列的 P0**（`CHECKPOINT1_PROGRESS_E.md` 第六节原文：「与上游模块完成真实接口联调 → 上游去 Mock，端到端消费 visual_evidence」），但现在他们跳过去做四阶段重训了。

### 🔴 卡点 2：四阶段训练路线方向错了

队友提的：FFHQR 二分类 → RetouchingFFHQ 单项+强度 → PPR10K 调色 → 混合测试。

问题：
- **阶段一要训的东西，V2 已经训完了** —— 推倒重来
- RetouchingFFHQ 65 万张、PPR10K 也不小，下载 + 预处理 + 训练以天计
- 他们自己的文档 5.8 写着：**本地 PyTorch 是 CPU 版，RTX 5070 根本没用上**
- 产出是权重文件，**评委看不见**；而评委一眼就能看见 demo 是假的
- 阶段四「区分产品效果/人像修饰/整体调色/拍摄条件变化」确实是核心目标，但它**不需要等模型训完**——用经典图像算法就能先做出来

### 🟠 卡点 3：before/after 的默认结论方向反了

代码里，没有输入信号时返回：**所有维度 Similar + 归因强度 Strong**，等价于"没做任何计算，就告诉用户这个效果可以归因于产品"。

这跟整个项目"证据不足不判真"的原则**正好相反**。应该默认 `Unknown`。

### 🟠 卡点 4：评测数字经不起问

三个致命问题：
1. 100 对数据 80/10/10 → **测试集只有 10 对**，任何准确率都是噪声
2. TruFor 那个"FPR=0% / TPR=100%"是拿 **4 个模拟分数**重算的，不是真实推理（交付物里没权重、没推理脚本、没像素掩码，他们文档已承认）
3. `data/benchmark_summary.json` 里的 F1=0.78、Pixel F1=0.64、一致性 0.73 全是**手写占位**，无来源；case_results 三条 expected==actual 全 pass，是 mock 自测自己（循环论证）

**这些数字现在就摆在"评测工作台"页面上展示。**

### 🟡 卡点 5：AI 生成检测完全空白

产品四档里有"包含 AI 生成部分"这一档，但目前没有任何实现。

### 🟡 卡点 6：C2PA 永远 Unknown

实现上直接返回 `error`。方案文档把它定位成"高权重硬证据"，实际永远拿不到——**要么用 `c2pa-python` 做实，要么从对外叙事里降级**，不能两头都占。

### 🟡 卡点 7：数据的域差距 + 许可

- FFHQ 是 **AI 生成的假脸**，真实种草是手机拍的真人 + 滤镜 + 平台压缩，指标不能外推
- FFHQR 标签只有二分类，**没有单项操作、也没有强度等级**（他们的 DATASET_CARD 白纸黑字写着"不得用它单独训练修饰强度分类器"）
- **FFHQR 是 CC BY-NC-SA 4.0 非商业许可**，比赛/展示前要确认赛方是否接受

### 🟡 卡点 8：分工漂移

文档分工是「成员 2 溯源 + 成员 3 归因」，但现实里 2/3 合并成 E 模块专做模型训练，导致：
- 没人做 before/after 对齐与条件一致性（原成员 3 的活）
- 没人推联调（原成员 1 的活，但接口在 2/3 手上）
